# Casement Host 1.7 release

## Source and artifacts

Release source: `50dfc98` ("Set Casement Host to 1.7") on `main`, tagged `host-1.7`. Mac version 1.7, build
6; Windows version 1.7 for x64 and ARM64. It ships everything merged since 1.6: both hosts' session modules
(PR #20), the video-freeze fixes, the Mac virtual display sized in points, and the ARM64 package fix (#18).

[Host 1.7](https://github.com/dlev02/Casement/releases/tag/host-1.7) was published as the latest stable
release with eleven assets. [Release log](../releases/host-1.7.md).

## Mac

`scripts/make-mac-release.sh 1.7` made a Release archive and Developer ID export. Apple accepted the app
(`4ef3b953-5940-4486-b448-23dfbcfcb877`) and the DMG (`d90a6697-c8ba-4f6b-9a7e-3f4f45c3f986`), and the
DMG's ticket was stapled and validated. `spctl` reports Notarized Developer ID for both. The app reads 1.7
(6), and the appcast's Ed25519 signature over the zip was checked with CryptoKit against the shipping
`SUPublicEDKey`. The Release binary wasn't launched.

## Windows

Built on the PC from the exact commit in a fresh worktree with `scripts/make-release.ps1 -Version 1.7`.
Tests: 559 total, 555 passed, 0 failed, 4 opt-in skipped. Checksums, manifest URLs, hashes and sizes were
checked on the PC and again on the Mac. The manifest signature verifies against `ReleasePublicKeyHex` and
a one-byte change is rejected. `check-package-arch.ps1` found no binaries for the other processor in
either package (302 checked for ARM64). Installers and the updater weren't run.

## Smoke test (incomplete)

A Debug console host from the same commit ran with real capture on the PC's console session, port 47825,
and answered a golden `hello` from the Mac with a challenge over the tailnet, like the installed 1.6.
The interop suite (`WindowsHostInteropTests`) couldn't reach it from this Mac: its test helper's
connections opened and `send` completed, but no byte reached the PC or even a loopback `nc` listener,
while `nc` and a plain `xcrun swift` script with the same `NWParameters` sent fine. Something filtering
per process on this Mac (most likely Little Snitch) drops the test helper's traffic. Drew chose to
publish without the live streaming run.

## Live endpoints

All eleven asset digests matched the local files before publishing. Afterwards, anonymous
`releases/latest/download` requests for `appcast.xml`, `windows-update.json` and its signature returned
files byte-identical to the verified ones, and both Setup links and the DMG returned HTTP 200.

## Not proven

No client has streamed from a 1.7 host yet, no installed copy has updated to it, and ARM64 has never run
on ARM hardware. Artifacts: `~/Developer/Casement-Releases/host-1.7/` and `build/mac-release/1.7`.

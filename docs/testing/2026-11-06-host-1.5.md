`scripts/make-mac-release.sh 1.5` completed a universal x86_64/arm64 Release archive and Developer ID
export. App and DMG notarization both returned Accepted, and tickets were stapled and validated.
The script verified nested signatures, hardened runtime, no get-task-allow, and Gatekeeper acceptance.

- App notarization: `1da8d9e7-fb55-42bd-89ca-2c4458e7557a`.
- DMG notarization: `682d0d37-a638-4426-b106-7a4dc086c502`.
- The app’s actual compiled ICNS was extracted and visually checked: slate casement C with inset screen.
- Archive and appcast Ed25519 signatures were independently checked with CryptoKit against the public
  key embedded in the signed release app. This avoided a redundant `sign_update --verify` private-key
  lookup that waited for Keychain access; that verifier was stopped.
- Appcast version is 4, short version 1.5, minimum macOS 26.0. The download points to the versioned 1.5 ZIP.
- All published Mac asset digests match the local files and checksum list.

Packages and logs: `~/Developer/Casement-Releases/host-1.5/mac/`.

## Windows

A bounded build on the linked Windows machine used the same exact source, existing signing key,
and `WindowsHost/scripts/make-release.ps1 -Version 1.5`.

- x64 and ARM64 ZIPs and Setup installers built successfully.
- Existing suites: 540 passed, 0 failed, 4 opt-in live checks skipped.
- Packaged executable version and PE architecture, every executable/installer icon frame, all three
  themed in-app images and all four embedded tray glyphs were checked. Extracted artwork was visually
  inspected for both architectures.
- The protected updater key’s public half matched the embedded Windows key; no private key was copied,
  printed or replaced. Parent independently verified the downloaded manifest’s Ed25519 signature with
  the shipping public key and the `casement-host-update-v1` domain prefix.
- Signed ZIP URLs, SHA-256 digests and sizes match GitHub’s published assets for both architectures.
  Both Setup files also match the checksum list. The seven Windows assets were uploaded before publication.

Windows evidence remains under the project’s `WindowsHost/release-shots/1.5/`, including `REPORT.md`
and `../Casement-Host-1.5-Windows-evidence.zip`. Build/test processes were stopped. No installer swap,
live updater restart, shared-settings preview or ARM hardware run was performed. The installed Host
was preserved, including its original process ID/start time and active connections.

## Live endpoints and installed copies

Publication was read back from GitHub’s latest-release API. All eleven assets and both signed update
feeds were validated before publication. Anonymous GETs of the latest Mac appcast and Windows manifest/
signature returned HTTP 200, resolved to host-1.5, and matched the verified asset digests. Both Windows
Setup latest-download URLs also returned HTTP 200 and resolved to 1.5. Python’s first HTTPS check timed
out during TLS negotiation; curl completed the same checks with normal certificate validation.
Public endpoint responses and verification records are retained with the release evidence.

The installed Mac Host was still 1.4 (3) when read after publication. Native UI inspection timed out,
so no installed updater/restart success is claimed. The Windows installed copy was deliberately left
running. Existing 1.4 installations can use Settings > General > Updates; automatic installation waits
for idle state and finished connections/transfers. Hosts before 1.4 need a manual download once.

## Release workflow

Build both platforms from one committed version before marking a GitHub release latest. Stage all
platform downloads, checksums and signed updater feeds on the same draft first. Verify feed signatures
against the public keys in the shipping apps, not merely the key used to sign them. Check each signed
manifest’s URLs, hashes and sizes against uploaded asset digests, then publish and verify anonymous
`releases/latest/download` endpoints. Keep source push, release publication and installed rollout
as separate proof states.

# Casement Host 1.8 release

## Source and artifacts

Release source: `cdb0159` on `main` (the merge of PR #22), tagged `host-1.8`. Mac version 1.8, build 7;
Windows version 1.8 for x64 and ARM64. [Host 1.8](https://github.com/dlev02/Casement/releases/tag/host-1.8)
was published as the latest stable release with eleven assets. [Release log](../releases/host-1.8.md).

## Before the merge

Five branches were merged into one and checked together: `CI=1 scripts/check.sh` and the visionOS build
passed, CI's `apple`, `windows` and `rules` jobs passed on the final commit, and both protocol suites
passed after the golden vectors were regenerated on both sides (70 Swift, 282 C#). A Debug iOS client
from the merged branch was run in an iPad Pro simulator against a synthetic host: the Settings sheet,
connecting with the fitted-picture cover clearing, Quality switching on the same encoder session, the
dictation panel and history, a Trackpad & Keyboard session, and the locked banner.

## Mac

`scripts/make-mac-release.sh 1.8` made a Release archive and Developer ID export, notarized the app and
the DMG, and stapled the DMG (`stapler validate` passes; `spctl` reports Notarized Developer ID). The
appcast names build 7, version 1.8 and the `host-1.8` download URL. The Release binary wasn't launched.

## Windows

Built on the PC from the exact commit in a fresh worktree with `scripts/make-release.ps1 -Version 1.8`.
Tests: 579 total, 575 passed, 0 failed, 4 opt-in skipped. Checksums were checked on the PC and again on
the Mac; the manifest's URLs, hashes and sizes match the zips; its signature verifies against
`ReleasePublicKeyHex` and a one-byte change is rejected. `check-package-arch.ps1` passed for both
packages (304 binaries for x64, 303 for ARM64). `CasementHostService.exe` is in both zips for the right
processor. The installers' payload wasn't opened, and neither installers nor the updater were run.

## Live endpoints

All eleven asset digests matched the local files before publishing. Afterwards, anonymous
`releases/latest/download` requests for `appcast.xml`, `windows-update.json` and its signature returned
files byte-identical to the verified ones, and both Setup links and the DMG returned HTTP 200.

## Checked on a real PC before release

On the PC's console session (RTX 5070 Ti, 4K): a fitted connect needs about 1.3 s after the scale change
before the taskbar has redrawn, so the wait is 1.2 s; a Quality change applies without a restart; a
reconnect within 3 s keeps the fitted mode, a deliberate close restores at once, and a drop restores
after 10 s. NVIDIA's encoder ignores the QP ceiling, so the still-screen sharpening pass does nothing
there.

## Not proven

- Casement Host Service has never run: installing it, answering an administrator prompt, the PIN at
  the lock screen, Task Manager through it, and uninstalling all need someone at the PC to approve the
  install prompt.
- Local network connections on a real network or over a cable, and the Local Network permission
  prompts on either end.
- Trackpad & Keyboard and Apple Pencil against a real Mac; Face ID unlock from the locked banner.
- No client has streamed from a 1.8 host installed from these files, no installed copy has updated to
  it, and ARM64 has never run on ARM hardware.

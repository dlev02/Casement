# Casement connects over the person's tailnet, and on their own local network once paired

**Original decision (2026-09)**: Casement and Casement Host talked only over Tailscale. The host's listener refused any peer outside Tailscale's CGNAT and ULA ranges (loopback only in Debug builds), and there was no relay server, account system, LAN discovery or port forwarding. Tailscale gives every device a stable address, encryption and access control, so Casement needs no servers of its own, collects nothing, and has nothing to keep running; pairing and Ed25519 keys on top prove which device and which computer are talking. The cost was that every connection needed Tailscale running on both ends, even with the iPad on the desk next to the Mac, and a Mac whose `.local` name or LAN address changed couldn't be found any other way.

**Lifted in part (2026-11-22, Drew's decision)**: a computer may also be reached directly on the local network or over a cable, as well as over Tailscale:

- **Opt-in on both ends.** Casement Host for Mac → Settings → General → Local network connections, and Casement → Settings → Connection → Local Network. Both are off by default. The Windows host stays tailnet-only for now.
- **Only already-paired devices.** The host refuses pairing from a local peer. A device pairs over Tailscale, where it learns the host's key, so a first pairing can't be answered by a device in the middle of a shared network.
- **Casement's own encryption.** Off the tailnet nothing else protects the stream, so the host refuses a local peer that doesn't offer an X25519 key share. Both handshake signatures cover both shares, and everything after the challenge is ChaCha20-Poly1305 records (`SessionCrypto`). Inside Tailscale the share is ignored and the stream stays as it was: WireGuard already seals it, and double encryption would only cost CPU.
- **Found by key, not by name.** The host advertises `_casement._tcp` over Bonjour with its key's fingerprint, and the device matches saved computers by the key it paired with, so a renamed or readdressed Mac is still found. That's only a hint: the handshake must still prove the key. The device tries the local route first and falls back to Tailscale at once, away from home or when anything about the local route is off.
- **Never the internet.** The host accepts private and link-local addresses only, so a forwarded port can't expose it.

Still out of scope, and needing Drew's decision first: pairing without Tailscale (which would need a PAKE over the six-digit code), connections from public addresses, and any relay or account server.
